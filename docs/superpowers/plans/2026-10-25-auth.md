# Accounts and Sign-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every character has an owner enforced by the server. Sign-in (Google, Discord, email link) turns sync on. The app keeps working signed out, with one local store per account.

**Architecture:**
- **Server:**
  - Better Auth runs in a catch-all pages route, storing users and sessions in the existing MongoDB.
  - `server/session.ts` turns a request into an owner id: session user, checked against the `X-WCG-Store-Owner` header.
  - `server/character-store.ts` scopes every query by owner.
- **Client:**
  - `helpers/offline/active.ts` owns "which IndexedDB store is active" and the one sync engine bound to it.
  - `helpers/offline/account.ts` owns the remembered account, startup reconciliation and sign-out.
  - `helpers/offline/adopt.ts` moves signed-out characters into an account.

**Tech Stack:**
- `better-auth` 1.7.13 and `@better-auth/mongo-adapter` 1.7.13, both pinned
- Next 16 pages router, MongoDB driver 7, Dexie 4
- `bun test`, with MongoDB running for server tests
- Resend called with `fetch`: no SDK dependency

**Spec:** `docs/superpowers/specs/2026-10-25-auth-design.md`

## Global Constraints

- **Session:** `expiresIn` 30 days (`60 * 60 * 24 * 30`), `updateAge` 1 day (`60 * 60 * 24`). Cookie cache off.
- **Email link:** expiry is the plugin default, 5 minutes.
- **Mongo adapter:** `mongodbAdapter(db)` with no `client` option (standalone Mongo, no transactions).
- **Store names:** signed out is `wcg`; an account is `wcg-u-<userId>`.
- **Remembered account:** `localStorage` key `wcg-account`.
- **Header:** `X-WCG-Store-Owner` on every `/api/characters/**` request. Missing or different from the session user means 401.
- **Portrait types:** only `image/jpeg`, `image/png`, `image/webp`; anything else is 415.
  - Portrait GET sends `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'`.
- **Someone else's character** gets 404 `{ message: 'No such character' }`. Never a 409 containing their data.
- **Exact copy:**
  - "Sign in to sync"
  - "Add N characters made on this device while signed out to your account?" with **Add** / **Not now**
  - "Signing out needs a connection"
  - "N changes on this device haven't synced yet. They'll sync next time you sign in here."
  - "Signing in needs a connection. You can keep playing; your characters will sync after you sign in."
  - "Check your email"
- **Not deployed:** no migrations or compatibility shims. README tells developers to drop the dev `characters` and `portraits` collections.
- **Every task ends green** on `bun test`, `bunx tsc --noEmit -p .` and `bun run check`.

## Review Focus

1. **Open redirect through sign-in's `next` parameter.** `/sign-in?next=https://evil.example` must land on `/`, not off-site. Task 6 test `safeNext rejects off-site targets`.
2. **Sign-in finishing in another tab of the same browser.** The original tab must switch to the account's store without a reload. Task 4 test `storage event switches the active store`.
3. **Production started without `RESEND_API_KEY`.** It must fail loudly rather than print sign-in links to logs. Task 2 test `email sender refuses console fallback in production`.
4. **An email-link user has no name.** The account menu and remembered account must still show something: the email. Task 4 test `remembered account falls back to email for display name`.
5. **Account linking with an unverified email.** A Discord account with an unverified email must not take over a Google account.
   - The spec said linking is "on, for trusted providers". Better Auth's `trustedProviders` _skips_ the email-verification check, so this plan leaves `trustedProviders` unset. Linking then happens only for verified emails, which Google and email links always are.
   - No automated test (that would be testing the library); the reviewer checks `server/auth.ts`.

  - `activateStore(userId: string | null): void`:
    - a no-op if it is already active
    - otherwise it opens `new WcgDb(storeName(userId))`, disposes the old engine, and creates and starts an engine when `userId` is set
    - then it notifies subscribers

  - `getSyncStatus(): SyncStatus` and `subscribeSync`, delegating to the current engine. With no engine: `{ online, syncing: false, pending: 0, conflicts: 0, lastError: null, signedOut: true }`. Notifies on engine swap.

  - `toAccount(user: { id: string; name?: string | null; email: string; image?: string | null }): Account`
  - `getRememberedAccount(): Account | null` and `rememberAccount(account: Account | null): void`. The latter writes `wcg-account`, then calls `activateStore`.
  - `startAccounts(lookup?: () => Promise<Account | null>): Promise<() => void>`. The default lookup is `authClient.getSession()` mapped with `toAccount`. It:
    1. activates the remembered account (or `null`)
    2. installs the `storage` listener for `wcg-account`, which re-activates from the new value
    3. if `navigator.onLine`, runs the lookup and reconciles per the spec:
       - a session user that differs from, or exists without, a remembered account gets remembered
       - no session keeps the remembered account

    It returns cleanup.
  - `signOutOfDevice(confirmUnsynced: (count: number) => Promise<boolean>, signOut?: () => Promise<unknown>): Promise<'offline' | 'cancelled' | 'done'>`. The default `signOut` is `authClient.signOut()`.
- Produces, in `helpers/auth-client.ts`: `authClient = createAuthClient({ plugins: [magicLinkClient()] })` from `better-auth/react`.
- Hooks read the active DB through `useSyncExternalStore(subscribeActive, getActiveDb, getActiveDb)` and pass it in `useLiveQuery` deps.
- `_app.tsx` calls `startAccounts()` in place of `startSync()`.
